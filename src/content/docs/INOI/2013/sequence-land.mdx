## Abridged statement

Each of the $N$ residents of Sequence Land is identified by an id, which is a sequence of distinct
integers. Two people are relatives if their ids have at least $K$ elements in common. The extended
family of a person is everybody reachable from them by following the relative relation repeatedly.
The President is given first. Find the size of the President's extended family.

$1 \le N \le 300$ and $1 \le K \le 300$, each id holds between $1$ and $300$ elements, and every
number in an id is between $0$ and $10^9$. The limits are 2 seconds and 64 MB.

## Editorial

### It is a connected component

"Relatives of relatives of relatives, without any limit" is the definition of reachability. Build a
graph with one vertex per resident and an edge between any two people who are relatives, and the
extended family of the President is exactly the connected component containing them. The answer is
the size of that component.

So the whole problem is deciding which pairs get an edge.

<details>
<summary>Hint 1</summary>

Look at the constraints before reaching for anything clever. $N \le 300$ means there are only
$\binom{300}{2} = 44850$ pairs to consider.

</details>

<details>
<summary>Hint 2</summary>

For a single pair, you need the size of the intersection of two lists of at most $300$ numbers.
The numbers go up to $10^9$, so you cannot index an array by value, but nothing stops you sorting
each id once at the start.

</details>

<details>
<summary>Key idea</summary>

<Aside type="tip" title="Key idea">
Sort every id, count each pair's common elements with a two pointer walk, then run a flood fill
from the President.
</Aside>

Checking every pair is $44850 \times 300$ steps, roughly $1.3 \times 10^7$. That is nowhere near
the limit, so no cleverness is needed.

</details>

### Counting the common elements

Sort each id once, up front. Two sorted lists can then be compared in a single walk: hold a pointer
into each, and at every step either both pointers see the same number, which is one common element
and both advance, or the smaller one advances. That is $O(p + q)$ for lists of length $p$ and $q$.

A hash set per id works just as well. Sorting is easier to reason about, and since ids have no
duplicate elements there are no edge cases around repeats.

Once the graph is built, a breadth first search from the President visits exactly their extended
family, and counting the visited vertices gives the answer.

Both subtasks are the same problem. The first one caps id lengths at $10$ instead of $300$, which
only makes the pair comparison cheaper, so the code below clears both.

### Implementation

```cpp title="sequence-land.cpp"
#include <bits/stdc++.h>
using namespace std;

int countCommon(const vector<int> &p, const vector<int> &q) {
    int i = 0;
    int j = 0;
    int common = 0;
    while (i < (int)p.size() && j < (int)q.size()) {
        if (p[i] == q[j]) {
            common++;
            i++;
            j++;
        } else if (p[i] < q[j]) {
            i++;
        } else {
            j++;
        }
    }
    return common;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;

    vector<vector<int>> id(n);
    for (int i = 0; i < n; i++) {
        int p;
        cin >> p;
        id[i].resize(p);
        for (int j = 0; j < p; j++) {
            cin >> id[i][j];
        }
        sort(id[i].begin(), id[i].end());
    }

    vector<vector<int>> adj(n);
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (countCommon(id[i], id[j]) >= k) {
                adj[i].push_back(j);
                adj[j].push_back(i);
            }
        }
    }

    vector<bool> seen(n, false);
    queue<int> todo;
    seen[0] = true;
    todo.push(0);

    int total = 0;
    while (!todo.empty()) {
        int u = todo.front();
        todo.pop();
        total++;
        for (int v : adj[u]) {
            if (!seen[v]) {
                seen[v] = true;
                todo.push(v);
            }
        }
    }

    cout << total << '\n';
}
```

Time complexity: $O(N^2 L)$ for the pair comparisons, where $L$ is the longest id, plus $O(N^2)$
for the search. Memory is $O(NL + N^2)$.

### Worked example

The sample has $K = 2$, the President with id $(4, 6, 7, 8)$, and three other residents with ids
$(8, 3, 0, 4)$, $(0, 10)$ and $(1, 2, 3, 0, 5, 8)$.

| pair | common elements | relatives? |
| :--- | :--- | :---: |
| President, $(8,3,0,4)$ | $\{4, 8\}$ | yes |
| President, $(0,10)$ | none | no |
| President, $(1,2,3,0,5,8)$ | $\{8\}$ | no |
| $(8,3,0,4)$, $(1,2,3,0,5,8)$ | $\{0, 3, 8\}$ | yes |
| $(8,3,0,4)$, $(0,10)$ | $\{0\}$ | no |
| $(0,10)$, $(1,2,3,0,5,8)$ | $\{0\}$ | no |

The President reaches $(8,3,0,4)$ directly, and through them reaches $(1,2,3,0,5,8)$. Only
$(0,10)$ is left out, so the extended family has size $3$.
